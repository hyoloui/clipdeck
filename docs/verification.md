# Clipdeck 최종 확인

다음 할 일: 0단계의 첫 명령을 터미널에 붙여넣는다.

이 문서는 구현자들이 샌드박스 때문에 못 한 확인을 한곳에 모은 것이다. 자동 테스트는 189개가 통과했다. 여기 항목은 앱을 실제로 띄워서 눈과 손으로 확인한다.

읽는 법
- 위에서 아래로 한 묶음씩 한다. 한 묶음은 5개 이하다.
- 항목 형식은 `- [ ] 무엇을 한다 → 기대 결과`다.
- 실패하면 그 자리에서 멈추지 말고 표(끝부분)에 메모만 적고 다음으로 간다.
- 항목 끝의 "(기대 결과 미확정)"은 보고서에 기대 결과나 방법이 분명하지 않다는 뜻이다. 눈으로 보고 판단한다.

---

## 0단계. 설치 (5분)

자기 터미널(샌드박스 밖)에서 순서대로 실행한다.

1. 저장소 폴더로 간다.

```sh
cd ~/Desktop/project/clipdeck
```

2. 서명 인증서가 있는지 본다. 한 줄이 나오면 3번은 건너뛴다.

```sh
security find-identity -v -p codesigning | grep "Clipdeck Local Signing"
```

3. 인증서가 없을 때만 만든다. 키체인 승인 창이 뜨면 허용한다. 이미 있으면 "이미 있음(유효): Clipdeck Local Signing"을 출력하고 끝난다.

```sh
scripts/make-signing-cert.sh
```

4. 빌드하고 설치하고 실행한다.

```sh
scripts/bundle.sh
```

5. 서명을 확인한다.

```sh
codesign -dvv ~/Applications/Clipdeck.app 2>&1 | grep Authority
```

6. DB 버전을 확인한다.

```sh
sqlite3 ~/Library/Application\ Support/Clipdeck/clipdeck.sqlite "pragma user_version"
```

7. 예전 큰 항목이 남아 있는지 확인한다.

```sh
sqlite3 ~/Library/Application\ Support/Clipdeck/clipdeck.sqlite "SELECT COUNT(*) FROM items WHERE length(CAST(plain_text AS BLOB)) > 65536"
```

8. 다른 클립보드 앱을 종료한다. 다른 클립보드 앱도 같은 ⇧⌘V를 쓰므로 켜 두면 Clipdeck의 단축키 등록이 실패한다.

9. 손쉬운 사용 권한을 허용한다. 시스템 설정 > 개인정보 보호 및 보안 > 손쉬운 사용에서 Clipdeck을 켠다. 이 권한이 있어야 ↩로 바로 붙여넣어진다. 처음 ↩를 누르면 시스템 권한 창이 한 번 뜬다.

**0단계 확인**

- [ ] `scripts/bundle.sh`가 끝나고 "설치 완료: …/Clipdeck.app" 다음 줄에 "MCP 클라이언트(Claude Code 등)를 다시 시작해야 새 clipdeck-mcp가 쓰입니다"가 나온다 → 두 줄이 보이고 인증서 경고(임시 서명)가 없다. 메뉴바에 Clipdeck 아이콘이 있고 Dock에는 없다
- [ ] 서명 명령 → `Authority=Clipdeck Local Signing`이 보인다
- [ ] DB 버전 명령 → `2`
- [ ] 큰 항목 명령 → `0`. 0이 아니면 패널에서 그 항목을 지우거나 메뉴바의 "기록 전체 삭제…"를 쓴다
- [ ] 다른 클립보드 앱 종료와 손쉬운 사용 허용 → Clipdeck이 시스템 설정의 손쉬운 사용 목록에서 켜져 있고, 시작할 때 "⇧⌘V를 등록하지 못했습니다" 안내가 뜨지 않는다

## 1단계. 핵심 흐름 (먼저 이것만)

이 5개가 통과하면 매일 쓸 수 있다고 판단한다. 안 되면 아래 묶음으로 가지 말고 "문제가 생기면"으로 간다.

1. 메모 앱이나 Ghostty 같은 평소 쓰는 앱을 앞에 둔다.
2. 텍스트 하나를 ⌘C로 복사한다.
3. 0.5초 안에 ⇧⌘V를 누른다.

- [ ] 복사 직후 0.5초 안에 ⇧⌘V → 패널이 화면 중앙에 바로 뜨고 검색창에 커서가 있고, 방금 복사한 항목이 맨 위에 있다
- [ ] 패널에서 글자를 타이핑(한글과 영문 각각) → 목록이 즉시 걸러진다. 결과가 없으면 "찾는 항목이 없습니다"가 나온다
- [ ] 항목을 고르고 ↩ → 원래 앱의 커서 자리에 바로 붙는다
- [ ] 붙인 직후 바로 타이핑 → 원래 앱에 포커스와 커서가 그대로 있다. 다른 앱으로 튀지 않는다
- [ ] 방금 붙인 항목 → 패널을 다시 열면 목록 맨 위에 있고 같은 항목이 중복으로 생기지 않는다

## 이후 단계

### **A. 패널 화면**

- [ ] 텍스트, 링크, 이미지, 파일, 색(예: 스크린샷, Finder 파일, 색상 값)을 각각 복사하고 패널을 연다 → 오른쪽 미리보기가 종류에 맞게 나오고 하단에 출처·시각·크기가 보인다
- [ ] 패널 전체를 본다 → 760×480 안에 검색창·목록·푸터가 모두 보이고 아래로 밀리거나 푸터가 잘리지 않는다. 검색창을 클릭하면 커서가 들어가고 패널이 움직이지 않는다
- [ ] 목록의 행을 본다 → 시각("12시간 전" 등)과 앱 이름이 잘리지 않고 긴 텍스트는 말줄임(…)으로 끝난다. 푸터에 "⌘H MCP 숨김"이 보인다
- [ ] 시스템 설정에서 밝은 모드와 어두운 모드를 번갈아 켜고 패널을 연다 → 두 모드 모두 색과 대비가 자연스럽다. 어두운 HUD로만 보이면 재질을 `.popover`로 바꿔야 한다
- [ ] Esc, 패널 밖 클릭, ⇧⌘V 재입력으로 각각 닫는다 → 약 0.12초 페이드로 닫히고 앞 앱의 활성 상태가 바뀌지 않는다. 페이드 중 ⇧⌘V를 다시 누르면 곧바로 다시 나타난다. ↩·⌘1–9·⌘C로 닫을 때는 즉시 사라진다

### **B. 패널 키**

- [ ] ↑↓ → 선택이 즉시 움직이고 긴 목록에서 선택 행이 보이도록 스크롤된다. ⌘W는 패널을 닫고 ⌘Q는 아무 일도 일으키지 않는다
- [ ] 검색창에서 ⌘V, ⌘A, ⌘X, ⌘Z, ⇧⌘Z → 모두 입력란 편집으로 동작한다
- [ ] 검색창에 글자를 쓰고 일부를 선택해 ⌘C → 그 글자가 복사되고 패널은 닫히지 않는다. 선택이 없을 때 ⌘C → 선택한 항목이 복사되고 패널이 닫힌다
- [ ] 검색창에 글자를 쓰고 ⌫를 길게 누른다 → 글자만 지워지고 목록 항목은 그대로다. 손을 뗀 뒤 0.5초 안에 ⌫를 한 번 더 눌러도 항목은 안 지워진다. 0.5초 뒤에 검색창이 빈 상태에서 한 번 누르면 선택 항목이 지워진다
- [ ] 한글 조합 중에 ↩ 한 번 → 조합이 확정되고 바로 붙여넣기가 실행된다. ↑↓와 Tab도 한 번에 동작하고, 이어서 타이핑해도 직전 음절이 중복 입력되지 않는다

### **C. 붙여넣기 (앱별)**

- [ ] Ghostty, 브라우저 주소창, Slack, 메모, Figma에서 각각 ↩ → 바로 붙는다. 설정에서 효과음을 켜 두면 Pop 소리가 난다
- [ ] ⇧↩ → 서식 없이 텍스트만 붙는다. VS Code에서 ⇧를 계속 누르고 있어도 Markdown 미리보기가 열리지 않는다. 설정의 "항상 일반 텍스트"를 켜도 같은 결과다
- [ ] 파일 항목과 이미지 항목을 ⇧↩로 붙인다 → Finder에는 파일이 붙고 이미지는 이미지로 붙는다
- [ ] ⌘3을 누른다(⌘를 누른 채 3을 누르고 ⌘를 늦게 뗀다) → 3번째 항목이 0.5초 안에 바로 붙는다
- [ ] Numbers나 Excel에서 셀 하나를 복사한다 → 패널에 텍스트 항목으로 보인다. ↩는 서식이 따라오고 ⇧↩는 텍스트만 붙는다

### **D. 붙여넣기 (예외 상황)**

- [ ] 손쉬운 사용 권한을 끈 상태에서 첫 ↩ → 시스템 권한 창이 한 번 뜨고 화면 아래(마우스가 있는 화면)에 "클립보드에 복사됨 · 바로 붙여넣기는 손쉬운 사용 권한 필요"가 뜬다. 글자 위를 클릭하면 손쉬운 사용 설정이 열린다. 두 번째 ↩부터는 권한 창이 다시 뜨지 않는다. 확인 뒤 권한을 다시 켠다
- [ ] ⌘C(복사만) → "클립보드에 복사됨"이 뜨고 붙여넣기는 일어나지 않는다. 파일이 여러 개인 항목을 복사하고 Finder에서 ⌘V하면 모두 붙는다
- [ ] 패널을 연 뒤 앞 앱을 종료하고 ↩, 또는 설정 창이 앞에 있을 때 패널로 붙여넣기 → ⌘V 없이 "클립보드에 복사됨"만 뜬다
- [ ] 빠르게 연속으로 붙여넣는다 → 마지막 것만 붙는다
- [ ] 설정의 붙여넣기 방식을 "클립보드에만 복사"로 바꾸고 ↩ → 붙지 않고 "클립보드에 복사됨"이 뜬다. 확인 뒤 원래대로 돌린다

### **E. 비밀값·숨김**

- [ ] 1Password에서 비밀번호를 복사한다. 설치돼 있지 않으면 키체인 접근에서 복사한다 → 패널에 항목이 생기지 않는다 (기대 결과 미확정: 1Password 번들 ID는 이 맥에서 확인하지 못했고 키체인 접근은 확인됨)
- [ ] 터미널에서 가짜 API 키를 만들어 복사한다 → 패널 행에 자물쇠와 앞 4자와 "••••"만 보이고 미리보기는 가려져 있다
```sh
printf 'sk-%s' "$(LC_ALL=C tr -dc 'A-Za-z0-9' </dev/urandom | head -c 40)" | pbcopy
```
- [ ] 가려진 항목에서 "보기"(클릭 또는 ⌘R)와 ⌘H → ⌘R은 내용을 보여 주고 ⌘H는 MCP 숨김을 켜고 끈다. ⌘H를 켜면 미리보기가 바로 자물쇠로 돌아간다
- [ ] 설정에서 "MCP에서 숨길 앱"에 메모를 넣고 메모에서 ⌘C 직후 ⌘Tab으로 다른 앱으로 간다. 이어서 패널을 연다 → 그 항목에 자물쇠가 있고 출처가 메모다. 같은 동작을 "제외 앱"에 넣은 앱으로 하면 기록에 남지 않는다
- [ ] 설정 개인정보 탭의 "화면 공유 중 숨김"을 켜고 화면 공유나 화면 녹화를 켠 채 패널을 연다 → 상대 화면이나 녹화에 패널이 보이지 않는다 (기대 결과 미확정: 확인 방법이 보고서에 없다)

### **F. Pinboard·필터**

- [ ] 항목을 고르고 ⌘P → 선택 행 근처에 보드 메뉴가 뜨고, 보드가 없으면 "새 보드 만들기…"만 있다. 이름을 입력해 만들면 그 보드에 항목이 들어간다. 탭 줄 끝의 "+"로도 보드를 만들 수 있다
- [ ] 보드 이름 시트에서 빈 이름과 중복 이름으로 만들기 → "보드 이름이 비어 있습니다."와 "같은 이름의 보드가 이미 있습니다."가 뜨고 시트가 다시 열린다. 시트가 떠 있는 동안 ⇧⌘V를 눌러도 패널과 시트는 그대로다
- [ ] 보드 이름 입력란과 시트 → ⌘V, ⌘A, ⌘C, ⌘X, ⌘Z가 동작한다. ⌘Q는 무반응이고 ⌘W는 시트를 취소한다
- [ ] Tab과 ⇧Tab → "기록"과 보드 탭 사이를 오간다. 보드가 없으면 탭은 "기록" 하나이고 빈 보드는 "이 보드는 비어 있습니다"가 나온다. 보드 탭에서 ⌫는 그 보드에서만 빼고 "기록" 탭에는 남는다. "기록" 탭에서는 항목이 삭제된다
- [ ] 검색창 오른쪽 [종류][앱][기간] 메뉴 → 한 줄에 들어가고 검색창이 너무 좁아지지 않는다. 종류, 앱(최근 출처 앱 최대 20개, 이름이 바뀐 앱은 최근 이름), 기간(전체 기간·오늘·최근 7일·최근 30일)을 고르면 목록이 즉시 걸러지고 결과가 없으면 "찾는 항목이 없습니다"가 나온다. 패널을 닫았다 열면 필터와 검색어가 모두 초기화된다

### **G. 설정 창 (일반·단축키)**

- [ ] 메뉴바 "설정…" → 설정 창이 열리고 탭 7개(일반·단축키·붙여넣기·기록·개인정보·Pinboard·MCP)가 보이며 탭을 바꾸면 높이가 내용에 맞는다
- [ ] 단축키 탭에서 패널 열기를 ⌥⌘V로 바꾼다 → ⌥⌘V만 동작하고 ⇧⌘V는 무반응이다. ⇧만 누르면 "⌘, ⌃, ⌥ 중 하나를 포함해야 합니다"가 뜬다. 다른 앱이 쓰는 조합이면 "이 단축키는 등록할 수 없습니다…"가 뜨고 이전 키가 유지된다. Esc는 취소이고 ⌫는 변경 없음이다. 확인 뒤 ⇧⌘V로 되돌린다
- [ ] 패널 키(예: 일반 텍스트 붙여넣기)를 ⌘P 같은 고정 키, 다른 슬롯의 키, ←/→, 전역 단축키와 같은 조합으로 바꾸려 한다. 전역 단축키를 ⌘P·⌘H·⌘W나 패널 키와 같게 바꾸려 해도 시도한다 → 모두 저장되지 않고 겹치는 동작 이름이 거부 문구로 보인다. 정상 변경 후에는 패널 푸터 힌트가 바뀐다
- [ ] 단축키 녹화 중에 ⇧⌘V를 누른다 → 패널이 열리지 않고 그 조합이 기록된다. 녹화 중 다른 앱 클릭, 다른 탭으로 이동, 다른 녹화기 클릭 → 앞 녹화가 취소되고 버튼 표시가 원래 키로 돌아온다
- [ ] 설정 창에서 ⌘W로 닫는다 → 창이 닫히고 직전에 쓰던 앱이 앞으로 돌아온다. 직전 앱을 종료한 뒤 닫으면 Clipdeck이 앞에서 내려간다(패널·설정 창이 남아 보이면 실패). 닫은 직후 패널 붙여넣기는 HUD가 아니라 원래 앱에 직접 붙는다

### **H. 설정 창 (기록·일반·권한)**

- [ ] 기록 탭에서 보관 기간을 줄인다 → 지울 항목이 있으면 "N개 항목이 지워집니다. Pinboard 항목은 지워지지 않습니다." 확인 창이 뜨고 취소하면 선택이 원래대로 돌아간다. 지울 항목이 0개면 창 없이 바로 바뀐다. 지울 항목은 보관 기간보다 오래된 항목이 있어야 생긴다. 없으면 0개 경로만 확인된다 (기대 결과 미확정: 오래된 항목을 만드는 방법이 보고서에 없다)
- [ ] 일반 탭 "로그인 시 실행"을 켠다 → 시스템 설정 > 일반 > 로그인 항목에 Clipdeck이 나타난다. 설정 창을 닫았다 다시 열면 토글이 시스템 설정 상태와 일치한다
- [ ] 일반 탭 "메뉴바 아이콘 표시"를 끈다 → 확인 창이 뜨고 아이콘이 사라진다. 패널에서 ⌘,로 설정 창이 열린다. 확인 뒤 다시 켠다
- [ ] 붙여넣기 탭의 손쉬운 사용 상태를 본 채 시스템 설정에서 권한을 껐다 켠다 → "허용됨"과 "필요함"이 1초 안에 바뀐다. 설정 창을 닫으면 이 갱신이 멈춘다
- [ ] 개인정보 탭과 MCP 탭에서 "앱 추가…"(/Applications에서 선택) → 앱 이름과 번들 ID가 목록에 나온다. MCP 숨김 앱을 추가하면 그 앱에서 이미 복사한 기존 항목도 숨겨진다

### **I. 설정 창 (MCP·Pinboard 탭)와 메뉴바**

- [ ] MCP 탭에서 실행 파일 경로와 등록 명령을 복사해 다른 곳에 붙여넣는다 → 경로와 명령 형태가 맞고, 복사한 내용이 Clipdeck 기록에 남지 않는다. 상태에 DB 경로와 전체 항목 수, MCP에 보이는 항목 수가 나온다
- [ ] Pinboard 탭에서 보드 이름 바꾸기 입력란에 ⌘V, ⌘A를 쓴다 → 동작한다
- [ ] 메뉴바 아이콘 > 일시정지(4종 중 하나)를 고른다 → 메뉴에 "일시정지 중(…까지)"가 보이고 아이콘이 `pause.circle`로 바뀐다. 이 동안 복사한 값은 패널에 저장되지 않는다. "재개"를 누르면 아이콘이 돌아오고 이후 복사는 저장된다. 기한이 있는 일시정지는 만료 시 아이콘이 자동으로 돌아온다
- [ ] 메뉴바 "기록 전체 삭제…" → 확인 창이 뜨고 확인하면 기록이 지워진다. 설정 기록 탭의 같은 삭제도 같은 확인 창이다 (기대 결과 미확정: 확인 창 문구와 Pinboard 항목이 지워지는지는 보고서에 없다)
- [ ] 메뉴바 "열기" → 패널이 열린다. 다른 앱이 ⇧⌘V를 쓰고 있는 상태에서 Clipdeck을 실행하면 "⇧⌘V를 등록하지 못했습니다 · 메뉴바에서 열 수 있습니다"가 약 1.2초 뜨고 로그에 "전역 단축키 등록 실패"가 남는다

### **J. MCP 등록**

설치한 앱이 오래됐으면 등록 스크립트가 "MCP 실행 파일이 응답하지 않습니다"로 멈춘다. 이 경우 0단계의 `scripts/bundle.sh`를 먼저 다시 실행한다.

```sh
cd ~/Desktop/project/clipdeck
scripts/register-mcp.sh --dry-run
```

- [ ] `scripts/register-mcp.sh --dry-run` → "정상 응답 확인"이 나오고 clipdeck add 계획이 claude·codex·antigravity 세 대상에 표시된다. 마지막에 "dry-run 완료: 아무것도 바꾸지 않았습니다."가 나온다
- [ ] 실제 등록을 실행한다 → 마지막 JSON 출력에 claude·codex·antigravity 세 `"target"`이 모두 있고 `"errors": 0`이며, 끝에 "완료: claude·codex·antigravity 세 대상이 모두 확인됐습니다."가 나온다 (기대 결과 미확정: 요청 문서의 "in sync" 문구는 스크립트에 없다)
```sh
scripts/register-mcp.sh
```
- [ ] 같은 명령을 한 번 더 실행한다 → 같은 결과가 나온다(이미 등록된 상태에서 `--replace`로 덮어쓴다). 이 재실행은 보고서에서 한 번도 실행된 적이 없다
- [ ] 스킬을 설치하고 세 파일이 모두 있는지 확인한다 → 세 파일이 모두 나온다. 보안 검사로 차단되면 `--force`를 쓰지 말고 출력을 보관한다
```sh
cd ~/Desktop/project/clipdeck
skillshare-managed install ./skill/clipdeck
ls ~/.config/skillshare/skills/clipdeck/SKILL.md ~/.claude/skills/clipdeck/SKILL.md ~/.gemini/antigravity-cli/skills/clipdeck/SKILL.md
```

### **K. MCP 호출 (세 LLM)**

등록 직후에는 각 LLM 클라이언트를 한 번 다시 시작한다.

- [ ] Claude Code에서 호출한다 → 숨김이 아닌 최근 항목 3개가 나온다
```sh
claude -p "clipdeck MCP의 list_recent로 최근 3개를 보여줘"
```
- [ ] Codex에서 호출한다 → 같은 종류의 항목이 나온다
```sh
codex exec "clipdeck MCP list_recent limit 3"
```
- [ ] Antigravity(agy)에서 같은 요청을 한다 → 같은 종류의 항목이 나온다 (기대 결과 미확정: agy의 실행 명령이 보고서에 없다. "clipdeck MCP의 list_recent로 최근 3개를 보여줘"를 agy 안에서 입력한다)
- [ ] MCP 도구 목록에 삭제 도구가 없다 → 이름 목록에 delete·remove 계열이 없다. 도구는 search_items, list_recent, get_item, list_pinboards, list_pinboard_items, copy_to_clipboard, create_text_item, add_to_pinboard 8개다
```sh
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | ~/Applications/Clipdeck.app/Contents/MacOS/clipdeck-mcp | grep -o '"name":"[a-z_]*"'
```

### **L. MCP 쓰기·숨김**

- [ ] 앱이 실행 중일 때 `copy_to_clipboard(text)`가 기록에 안 남는지 본다. 먼저 개수를 센다, 아무 LLM에서 "clipdeck의 copy_to_clipboard로 probe-xyz를 복사해줘"라고 시킨다, 다시 센다 → 전후 숫자가 같고 `pbpaste`가 `probe-xyz`를 출력한다
```sh
sqlite3 ~/Library/Application\ Support/Clipdeck/clipdeck.sqlite "select count(*) from items"
pbpaste
```
- [ ] 패널을 연 채로 다른 터미널에서 `create_text_item`을 호출한다 → 패널 맨 위에 `from-mcp`가 바로 나타나고, 선택해 둔 항목은 다른 항목으로 넘어가지 않는다
```sh
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"create_text_item","arguments":{"text":"from-mcp"}}}' | ~/Applications/Clipdeck.app/Contents/MacOS/clipdeck-mcp
```
- [ ] 가짜 키를 `create_text_item`으로 넣는다 → 응답이 "저장했지만 비밀값으로 판정되어 MCP에서 숨김 처리됨"이고 id가 없다. 이어서 `claude -p "clipdeck MCP의 list_recent로 최근 3개를 보여줘"`에 그 키가 나오지 않는다. 확인 뒤 패널에서 그 항목을 ⌫로 지운다
```sh
KEY="sk-$(LC_ALL=C tr -dc 'A-Za-z0-9' </dev/urandom | head -c 40)"
printf '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"create_text_item","arguments":{"text":"%s"}}}\n' "$KEY" | ~/Applications/Clipdeck.app/Contents/MacOS/clipdeck-mcp
```
- [ ] 터미널에서 `copy_to_clipboard`를 실제 클립보드에 쓰게 한다 → 응답이 `isError:false`이고 `pbpaste`가 `clipdeck test`를 출력한다. 사용자 클립보드를 덮어쓰므로 중요한 복사가 없을 때 한다
```sh
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"copy_to_clipboard","arguments":{"text":"clipdeck test"}}}' | CLIPDECK_DATA_DIR=$(mktemp -d) ~/Applications/Clipdeck.app/Contents/MacOS/clipdeck-mcp
pbpaste
```
- [ ] 클립보드 표시 테스트를 실제 클립보드로 실행한다 → 모든 테스트가 통과하고 건너뜀이 없다. 파일 2개 쓰기 시 첫 항목에 selfMarker가 있고 1바이트 표시 데이터가 누락되지 않는다는 뜻이다
```sh
cd ~/Desktop/project/clipdeck && swift test --filter ClipboardPayloadTests
```

### **M. 성능 측정**

- [ ] 유휴 CPU를 잰다. 5분 이상 건드리지 않은 상태에서 실행한다 → 두 번째 값이 1% 미만이다
```sh
top -l 2 -pid $(pgrep -x Clipdeck) -stats cpu
```
- [ ] 메모리를 잰다 → footprint가 80MB 미만이다
```sh
footprint Clipdeck
```
- [ ] 패널 표시 체감을 본다. 앱을 새로 실행한 직후 첫 ⇧⌘V와 그다음 ⇧⌘V를 비교하고, 큰 스크린샷(5K 등)이 맨 위일 때도 한다 → 둘 다 100ms 이내로 느껴지고 첫 표시도 이후와 비슷하게 빠르다. 패널을 연 직후 "앱" 메뉴의 출처 앱 목록이 채워져 있다 (기대 결과 미확정: os_signpost 측정은 구현돼 있지 않아 체감으로 판단한다)
- [ ] 큰 스크린샷이 맨 위인 채로 ↑↓를 오간다 → 끊김이 없고 레티나에서 흐리지 않고 미리보기가 바로 바뀐다. 패널을 닫았다 같은 항목이 맨 위인 채로 다시 열어도 미리보기가 나온다. 활동 모니터에서 패널을 닫은 뒤 메모리가 줄어든다
- [ ] 10MB 텍스트를 복사한다 → 앱이 멈추지 않고 ⇧⌘V가 평소처럼 열린다. 저장된 텍스트는 102400바이트 이하다. 확인 뒤 그 항목을 패널에서 지운다
```sh
yes "clipdeck 10MB test line" | head -c 10485760 | pbcopy
sleep 2
sqlite3 ~/Library/Application\ Support/Clipdeck/clipdeck.sqlite "select max(length(CAST(plain_text AS BLOB))) from items"
```

### **N. 재빌드·재부팅**

- [ ] 코드 수정 없이 `scripts/bundle.sh`를 다시 실행한다 → 서명 Authority가 그대로 `Clipdeck Local Signing`이고, 손쉬운 사용 권한을 다시 줄 필요 없이 ↩ 붙여넣기가 바로 동작한다
- [ ] 재빌드 뒤 `scripts/register-mcp.sh`를 한 번 더 실행하고 LLM 클라이언트를 다시 시작한다 → 세 대상이 다시 확인되고 새 `clipdeck-mcp`가 쓰인다
- [ ] 일반 탭에서 "로그인 시 실행"을 켠 채 Mac을 재부팅한다 → 로그인 뒤 메뉴바에 Clipdeck 아이콘이 있고 `pgrep -x Clipdeck`이 번호를 출력한다
- [ ] 재부팅 뒤 ⇧⌘V → 패널이 열리고 재부팅 전 기록이 남아 있다
- [ ] 위가 모두 통과하면 1주 실사용을 시작한다 → 다른 클립보드 앱은 종료해 두고, 1주 동안 복사 누락·패널 지연·붙여넣기 실패가 없는지 본다. 그 뒤 기존 앱을 삭제한다

## 문제가 생기면

로그를 본다.

```sh
log show --last 5m --predicate 'subsystem == "local.hyoloui.clipdeck"'
```

앱을 다시 설치한다.

```sh
cd ~/Desktop/project/clipdeck && scripts/bundle.sh
```

설정을 초기화한다. 앱을 종료한 뒤 실행하고 다시 켠다.

```sh
defaults delete local.hyoloui.clipdeck
```

데이터 폴더는 `~/Library/Application Support/Clipdeck`이다. 안에 SQLite 데이터베이스(`clipdeck.sqlite`)와 큰 표현 데이터 `blobs/`가 있다. `CLIPDECK_DATA_DIR` 환경 변수를 주면 다른 폴더를 쓴다. 실험할 때는 임시 폴더를 지정한다.

자주 있는 경우

- 단축키가 안 열린다: 다른 클립보드 앱이 켜져 있는지 본다. 로그에 "전역 단축키 등록 실패(상태 -9878)"가 있으면 다른 클립보드 앱을 종료하고 앱을 다시 실행하거나 메뉴바 "열기"를 쓴다
- ↩가 붙지 않고 "클립보드에 복사됨"만 뜬다: 손쉬운 사용 권한을 확인한다. 서명이 임시(ad-hoc)면 재빌드마다 권한이 풀리므로 `scripts/make-signing-cert.sh` 뒤 `scripts/bundle.sh`를 다시 한다
- 등록 스크립트가 "MCP 실행 파일이 응답하지 않습니다"로 멈춘다: `scripts/bundle.sh`를 다시 실행한다
- 실패 항목은 원인과 수정 방법을 함께 적어 조정자에게 전달한다
