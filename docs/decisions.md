# 조정자가 대신 내린 결정 (구현 중, 2026-11-21)

구현을 멈추지 않으려고 조정자가 사용자 대신 정한 것들이다. 순서는 내린 순서다. 틀렸다고 보이면 알려 주면 고친다.

4:## Rulings
- Ruling: 구현자를 병렬로 돌린다(작업별 git worktree ~/Desktop/project/clipdeck-wt/tN, 브랜치 tN, 파일이 겹치지 않는 작업만) — 사용자가 팀 분업·병렬을 명시 요청 — 병합 충돌 시 재작업
- Ruling: 병렬 파도: T1 → (T2∥T5) → (T3∥T4∥T6) → (T7∥T9) → (T8∥T10) → (T11∥T13) → T12 → T14
- Ruling: T1이 테스트 타깃 ClipdeckCoreTests·ClipdeckMCPKitTests 둘 다 선언(MCPKit은 자리표시 테스트 1개) — 빈 타깃은 빌드 실패 — 없음
- Ruling: T7은 MCPKit 테스트용 헬퍼를 자체 파일로 둔다(Core 테스트 헬퍼는 다른 타깃이라 못 씀)
- Ruling: 커밋 귀속은 Claude Fable 5.2 (세션 모델 변경)
- Ruling: GUI·권한이 필요한 확인 단계(키체인 승인, 손쉬운 사용)는 구현자가 가능한 범위까지만 하고 나머지는 T14 수동 목록으로 모은다
- Ruling: 저장소를 ~/Desktop/project/clipdeck 으로 이동(사용자 요청, 2026-11-21). worktree는 ~/Desktop/project/clipdeck-wt/tN
- Ruling: ld 검색 경로 경고는 CLT 환경의 알려진 잡음으로 기록 — 코드로 못 없앰 — 틀리면 T14에서 재확인
- Ruling: 커밋 trailer는 각 구현자 세션의 attribution(실제 모델)을 따른다 — 사실과 맞음 — 없음
- Ruling: 여러 단어 검색은 단어별 AND(각 단어 3자 이상 FTS, 미만 LIKE, 최대 8단어) — 스펙은 "즉시 FTS 검색"만 말하고, 구문 일치는 매일 쓰기에 부자연스러움 — 틀리면 searchSQL 한 곳 수정
- Ruling: 고엔트로피 대상은 [A-Za-z0-9_+=-]만으로 된 토큰으로 한정, 타입 이름 값만 키-값 제외 — 지시서의 엔트로피 조건이 실측 오탐을 냄(plan-mandated 일부) — `/` 포함 base64 단독 비밀값은 놓침(키 이름과 함께면 키-값 규칙이 잡음)
- Ruling(변경): 고엔트로피 허용 문자에 `/` 복원 — 재검토 실측: AWS 형식 키 탐지율 99%→51% — 점 없는 경로 오탐은 단어 조각 비율로 방어
- Ruling: 샌드박스에서 빌드는 --disable-sandbox, GUI·서명·설치 확인은 사용자 수동(명령 정리해 전달). 사용자 승인으로 /private/var/folders/wp/… 쓰기 허용 추가. dev 전체 테스트 51개 통과 확인
- Ruling: 필터 메뉴는 종류·앱 2개로 구현(스펙 §6.4·§2 "검색 + 필터"가 근거, 보드 범위 메뉴는 탭과 중복이라 생략). PanelModel에 kindFilter/appFilter 추가(계획 인터페이스 확장)
- Ruling: 퇴장은 120ms 페이드, 단 붙여넣기·복사로 닫을 때는 즉시(붙여넣기 지연 방지) — §6.9 "등장/퇴장"과 §3 "패널이 늦게 뜬다" 반목표의 절충
- Ruling: 보드 탭에서 ⌫는 보드에서만 뺀다 — 스펙 모호, 데이터 손실이 적은 쪽
- Ruling: MCP가 만든 텍스트는 hash 공간 분리(SHA256("mcp\0"+text)) — 캡처된 숨김 행과의 hash 충돌이 존재 확인 통로가 됨 — 같은 텍스트가 캡처분과 MCP분 두 행으로 중복될 수 있음
- Ruling(변경): JWT 조각 상한 2048 → 16384, `-` 뒤 JWT는 토큰 단위 보조 검사(선형)로 잡는다 — 재검토 실측 근거
- Ruling(변경): create_text_item은 중복 제거 없이 매번 새 행(hash에 UUID 포함) — bump 경로가 곧 누출 통로 — 같은 텍스트 반복 호출 시 항목 중복
- Ruling(계획 뒤집음): MCP가 클립보드에 쓰는 내용은 항상 selfMarker를 붙여 앱 감시기가 저장하지 않게 한다. id 복사는 MCP가 직접 사용 기록 갱신 — 계획의 "MCP 복사도 기록에 남게"가 숨김 존재 확인 통로가 됨 — copy_to_clipboard(text)는 기록에 안 남음
- Ruling: 일반 텍스트 필터는 파일 URL·이미지·색 표현이 있으면 적용하지 않는다 — 스펙 §6.5 "일반 텍스트 모드면 utf8-plain-text만"을 문자 그대로 적용하면 파일 붙여넣기가 깨짐 — 텍스트+이미지 혼합 복사(예: 스프레드시트 셀)는 일반 텍스트 모드에서도 이미지가 남음
- Ruling: id는 재사용하지 않는다(meta.next_item_id 카운터, 스키마 v2 마이그레이션) — 재검토 실측: create 응답 id와 get_item(id-1) 오류로 숨김 행 확정 가능 — 남는 한계는 "숨김인지 삭제인지 모호한 빈 번호"(1차 결정 수준)
- Ruling: create_text_item은 최근 1시간 MCP 생성 행 200개 초과 시 오류 — 루프에 빠진 LLM이 저장소를 채우는 것 방지 — 정상 사용에서는 닿지 않는 값
- Ruling: 모르는 도구 이름은 -32602(MCP 명세) — 클라이언트 호환 — 없음
- Ruling: 메인 메뉴(앱·편집·창)를 추가 — 설정 창 입력란 편집과 ⌘W에 필요 — 패널 키 모니터와 충돌 여부는 구현자가 확인
- Ruling: 지울 항목 0개면 보관 기간 확인 창 생략 유지, 수동 체크리스트 문구 수정
- Ruling: plain_text·FTS·get_item·비밀값 검사를 모두 앞 100KB로 통일 — 검사 범위 밖 텍스트가 MCP에 닿는 것이 누출 — 100KB 뒤 텍스트는 패널 검색에도 안 걸림(붙여넣기는 전문)
- Ruling: 출처·숨김·제외 판정은 직전 틱 이후 앞에 있던 앱 집합으로 — 복사 직후 앱 전환이 가장 흔한 흐름 — 숨길 앱 근처에서 복사한 다른 앱 항목이 숨겨질 수 있음(안전한 쪽)
- Ruling: 텍스트+이미지 복사는 텍스트로 분류(스펙 §6.3 판정 순서 변경) — 스프레드시트 셀이 "이미지"로 저장돼 검색 불가 — 이미지 편집기에서 텍스트 레이어와 함께 복사한 경우 텍스트로 보임
- Ruling: 날짜 필터 추가(스펙 §2) — 최종 검토가 누락 지적
- Ruling: ⌘는 붙여넣기 전 수정 키 대기에서 제외 — 보내는 이벤트가 ⌘V
- Ruling(보류 유지): 무작위 id로 개수 누출까지 막는 것은 하지 않고 스펙에 한계로 적는다 — 내용은 안 나오고 셸 경유 직접 열람이 이미 스펙의 한계
- Ruling(보류 유지): 사용자가 푼 숨김이 재복사에서 다시 숨겨지는 것은 그대로 — 안전한 쪽, 플래그 추가는 2차
- Ruling: 이번 변경 전에 저장된 행(v1, 앞 64KB만 검사·plain_text 전문 저장)은 재검사하지 않는다 — 실제 DB에 개발 중 시험 항목 7개뿐 — 사용자에게 설치 뒤 "기록 전체 삭제" 1회를 권고
- Ruling: 절차상 최종 수정은 1회지만, 남은 Important는 숨김 누출이고 한 줄 수정이라 같은 구현자에게 마지막 보완 3건을 맡긴다. 추가 검토 없이 조정자가 새 테스트 존재와 전체 테스트 통과를 직접 확인한다 — 알려진 누출을 남기는 것보다 낫다 — 이 보완은 독립 검토를 받지 않음
- Ruling: 기존 v1 행은 재검사 대신 설치 직후 질의(64KB 초과 plain_text 개수)로 확인하고 0이 아니면 그 항목을 지운다(재검토자 의견 반영)
